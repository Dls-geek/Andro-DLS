## Ring 0 Path Options

### Path A: Kernel Exploit (unlikely short-term)
- Kernel 5.10.246 — check for known CVEs (CVE-2024-xxxx)
- Requires: exact kernel headers, cross-compiler (aarch64-linux-android-clang), working exploit
- Risk: Kernel panic = device reboot, hard to debug

### Path B: Bootloader Unlock (not available)
- Infinix XOS locks bootloader
- Unlock voids warranty, requires factory reset

### Path C: Magisk via Patched Boot (needs unlocked bootloader)
- Same blocker as Path B

### Path D: Shell UID Maximization (DOABLE NOW)
- UID 2000 already has: `readproc`, `adb`, `sdcard_rw`, `readtracefs`
- Can access: `/proc/*`, `/data/misc/`, `/sys/`, dumpsys, bugreport
- **Approach:** Agent executes commands via an elevated shell path — not full root but maximum userland

## Masterpiece Agent v4 Design

### Architecture: Dual-Layer Agent

```
┌─────────────────────────────────────┐
│  Layer 1: HTTP C2 (Ring 3 — App)   │  ← Current v3, working
│  UID 10351, always-on Service       │
├─────────────────────────────────────┤
│  Layer 2: Shell Proxy (Ring 1)      │  ← NEW — elevates commands
│  Via ADB spwan → UID 2000           │     through ADB shell
└─────────────────────────────────────┘
```

### New Commands (Ring 1 Access)

| Command | Description | Access |
|---------|-------------|--------|
| `sys:proc:<pid>` | Read /proc/<pid>/maps, status, cmdline | UID 2000 readproc |
| `sys:net` | Read /proc/net/tcp, udp, raw | UID 2000 |
| `sys:packages` | List all installed apps (pm list) | UID 2000 |
| `sys:dumpsys <svc>` | Full dumpsys on any service | UID 2000 |
| `sys:bugreport` | Generate full system bugreport (big file) | UID 2000 |
| `sys:props` | All system properties (getprop) | UID 2000 |
| `sys:logs` | logcat with all buffers | UID 2000 log group |
| `sys:sensors` | Read /sys/class/ sensors | UID 2000 |
| `sys:battery` | dumpsys batterystats | UID 2000 |
| `sys:apps/<pkg>` | dumpsys package <pkg> | UID 2000 |

### Implementation

```java
// Agent v4 — adds ELV (elevated) command prefix
private String dispatch(String cmd) {
    String l = cmd.toLowerCase();
    // ... existing commands ...
    if (l.startsWith("elv:")) return shell(cmd.substring(4)); // Run via /system/bin/sh at UID 2000
    // Actually, agent's shell() already runs at whatever UID the service has.
    // The elevation comes from ADB, not from the agent process.
    // Solution: use ADB from host side, agent provides HTTP bridge.
    return shell(cmd);
}
```

**Correction:** The agent process runs at UID 10351 (app sandbox). Its shell commands also run at UID 10351. The ADB shell (UID 2000) is only accessible from the host, not from within the app.

**So the real architecture is:**

```
Host (our machine)                  Phone
┌──────────────────┐              ┌──────────────────┐
│  C2 Server (8080)│◄──HTTP C2──►│ Agent (UID 10351)│
│                  │              │                  │
│  ADB (USB)       │──ADB(2000)─►│ Shell (UID 2000) │
└──────────────────┘              └──────────────────┘
```

The host has BOTH the C2 server AND ADB. We can:
1. Receive commands via C2 from agent (Ring 3 data)
2. Execute elevated commands via ADB shell (Ring 1) from the host side

### Masterpiece Agent Architecture

Instead of a single agent, build:

1. **Agent v4 (on-device):** All current v3 capabilities + new per-app dump commands
2. **C2 Server v4 (host-side):** Orchestrates both HTTP C2 and ADB shell
   - Receives GET /cmd from agent → returns queued command
   - Can also run ADB shell commands and pipe results back via C2
   - Unified command queue: `sys:*` commands execute via ADB, others via agent
